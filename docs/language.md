# Pythonのどの機能を検証材料にできたか

[READMEに戻る](../README.md)。検証の書き方は[仕様と検証](proofs.md)、
実行手順は[環境](environments.md)を参照してください。

この文書は、このリポジトリで実際に試したPythonの機能と必要だった注釈を記録します。
Naginiの対応機能を網羅した一覧ではありません。
「未確認」は、このリポジトリでは試していないという意味で、非対応とは区別します。

## 今回の例で確認したこと

2026-10-10時点の結果です。整数の絶対値、範囲の和、リストの先頭の読み取りと書き換えという小さな題材での確認です。

| 機能・記法 | 題材 | 結果・必要だった条件 |
|---|---|---|
| `int`の引数と返り値 | 絶対値 | 型注釈を付けて検証できた |
| 比較・単項マイナス・`or` | 非負条件と絶対値の条件 | 二つの条件を検証できた |
| `if`、代入、`return` | 負数かどうかで分岐 | 正しい分岐は成功し、負数の分岐を壊すと失敗した |
| 通常の`assert` | 関数内部で結果を確認 | 実行時の具体例の検査にも、Naginiの静的検証にも使えた |
| 関数呼び出し | 絶対値を受け取る`caller` | 必要な返り値の保証を契約で宣言すると検証できた |
| `Ensures`、`ResultT` | 返り値の契約 | Naginiの仕様用記法。通常のPythonの機能ではない |
| `while`、加算・乗算、`+=` | 0からn未満までの和 | 範囲と途中の和を表す不変条件で最後のassertを検証できた |
| `Requires`、`Invariant` | ループの入力条件と途中の条件 | 検証用の宣言。この例では通常実行も可能だが、宣言自体が実行時に条件を強制するわけではない |

リストのスライス・別名参照、
辞書の書き込み・削除・走査、集合、クラスの継承・プロパティ、例外、外部ライブラリ、
ファイルやネットワークの入出力は未確認です。
公式の機能説明は[NaginiのREADME](https://github.com/marcoeilers/nagini)と
[仕様言語の説明](https://github.com/marcoeilers/nagini/wiki)を参照してください。
公式の説明だけを読んだ機能を、この表の実測結果には含めません。

## リストで確認した範囲

[list_head.py](../examples/list_head.py)は、空リストなら0、要素があれば先頭の値を返します。
通常のPythonでもそのまま実行でき、入力が変わらないことを具体例で照合しています。
返り値の仕様は、関数内の最後の二つのassertに置いています。

| 機能・記法 | 確認したこと |
|---|---|
| `list[int]` | 整数リストの引数を型注釈付きで扱えた |
| `len`と空の場合の分岐 | 要素がある場合にだけ添字0を読み、空なら0を返すことを検証できた |
| `values[0]` | リストを読む権限を指定して、添字の安全性と結果を検証できた |
| `Acc(list_pred(values), 1 / 2)` | 読み取り専用の権限を指定できた。同じ権限のまま要素へ書き込むコピーは拒否された |

権限の宣言を外した版はNaginiで失敗しますが、通常のPythonでは正しく動くことも確認しました。
この権限はOSのアクセス権ではなく、可変データを扱うための証明上の条件です。
通常の実行時にPythonのリストを読み取り専用に変える機能ではありません。
型検査で外部APIの不十分な注釈を扱った二か所は[環境の説明](environments.md)に記録しています。
詳しい成功・失敗の比較は[リストの実験](proofs.md)を参照してください。

## リストへの書き込みで確認した範囲

[list_write.py](../examples/list_write.py)は、空リストなら何もせず、
要素があれば先頭を指定値に置き換えます。たとえば`[7, 99]`に9を指定すると`[9, 99]`になります。
この例も通常のPythonでそのまま実行できました。

| 機能・条件 | 確認したこと |
|---|---|
| `values[0] = value` | 要素がある場合の添字代入を検証できた |
| `Acc(list_pred(values))` | 分数を省略した書き込み可能な権限で検証できた |
| 読み取り専用の権限への置換 | 書き込みの条件で権限不足を報告した |
| 長さと先頭の値 | 書き換え前の長さと等しく、非空なら指定値になることを最後のassertで検証できた |
| 先頭以外の要素 | 具体例の実行テストで維持されることを確認。現在の静的仕様では未保証 |

二つ目の要素を余分に書き換えるコピーは、長さと先頭の値の条件を満たすためNaginiで成功しました。
そのコピーは、先頭以外も含めた実行テストでは失敗します。
リストの書き込みに対応していることと、すべての要素への影響を仕様が縛っていることは別です。
境界を含めた比較は[書き込みの実験](proofs.md)に記録しています。

## 先頭以外を変更しないという仕様

[list_frame.py](../examples/list_frame.py)では、書き込み例と同じ処理に、
先頭以外のすべての要素が変更前の値と等しいという条件を加えました。
この条件もNaginiで成功し、二つ目の要素を余分に変更するコピーは拒否されました。
前節の弱い仕様の例は比較用に残しています。

`ToSeq(values)`は、静的検証では変更前の内容を表す変更できない列を作ります。
`Forall(int, ...)`は、対象となるすべての整数の添字について条件を要求します。
`Implies`で添字1から末尾までに対象を限定し、`Assert`でその条件を検証します。
実際にリストを走査するPythonのループを追加したわけではありません。

通常実行でも、この例の書き換えと具体例のテストは成功しました。
ただしNagini 1.3.1の`ToSeq`・`Forall`・`Assert`は実行時には検証用の値や検査を提供しません。
この式では比較をlambdaの中に置いているため、通常実行時には比較自体が評価されません。
従って、`Assert`の成功を実行時の全要素検査と解釈してはいけません。
詳しい比較は[変更範囲の実験](proofs.md)を参照してください。

## 検証できることと、Pythonで実行できること

通常のassertを使う[absolute.py](../examples/absolute.py)はPythonで実行でき、
[実行テスト](../tests/test_absolute.py)で選んだ入力について組み込みの`abs`と一致しました。

契約付きの[absolute_contract.py](../examples/absolute_contract.py)を直接実行するには、検証用の宣言を取り除く必要があります。
導入した版で`absolute(1)`を通常のPythonから直接呼ぶと、返り値を表す`ResultT(int)`が
`None`となり、`>= 0`の比較で`TypeError`になります。
2026-10-10に、[抽出スクリプト](../scripts/extract_absolute.py)で元のソースをNaginiで検証し、
二つの`Ensures`宣言と専用importだけを除去したコピーを実行できました。
計算する分岐・返り値と、呼び出し側の通常のassertは残しています。
負数・ゼロ・正数・大きな整数について、返り値が組み込みの`abs`と一致し、
呼び出し側も実行できることをテストしました。
生成手順は[環境の説明](environments.md)を参照してください。

この抽出は、今回のファイル構成と二つの契約宣言に限定した自作の処理です。
仕様や構成が想定と違えば停止し、実行部分に`Ensures`や`ResultT`が残る場合も拒否します。
ループ不変条件、別の契約、検証用の型などを一般的に除去する機能は試していません。
静的検証と、生成されたコピーの実行テストを合わせて確認した範囲の結果です。

## whileループの例を通常のPythonで動かす

[sum_range.py](../examples/sum_range.py)は、0からn未満までの整数を順番に足します。
たとえば`sum_range(4)`は`0 + 1 + 2 + 3`で6、`sum_range(0)`は0です。
このファイルは、導入済みのNagini 1.3.1の`Requires`と`Invariant`をimportしたまま
通常のPythonで実行できました。返り値を参照する`ResultT`や`Ensures`は使っていません。
前回の絶対値専用の抽出処理を、ループ用に拡張した結果ではありません。

`Requires(n >= 0)`は静的検証の入力条件です。通常のPythonで入力を拒否するためには
別のチェックが必要で、この例は`assert n >= 0`も置いています。
`Invariant`は検証時にループの途中で保たれる条件を伝える宣言で、
通常実行時に条件が真であることを強制する機能ではありません。
最後の通常のassertは、静的検証でも実行テストでも確認しています。
実行テストはassertが有効な通常のPythonで行い、`python -O`は対象外です。

検証の仕様は関数内の最後のassertに置いています。
返り値の保証を別の呼び出し側へ伝える契約や、一般的な停止性の検証は今回の対象外です。
詳しくは[ループの実験](proofs.md)を参照してください。

## リストの保証を呼び出し側へ渡す

[list_contract.py](../examples/list_contract.py)では、非空の整数リストの先頭を書き換えます。
入力の条件を`Requires`、関数が戻る時点の保証を`Ensures`で指定します。
この例の事後条件は、書き込み権限の返却、長さの維持、先頭が指定値になることです。
`Old(len(values))`は、関数に入る前の長さを参照します。

呼び出し側はその契約を使い、長さと先頭の値を確認した後、先頭をさらに書き換えられました。
返却権限を読み取り専用に弱めると、呼び出し側での代入が拒否されます。
先頭の値の事後条件を省くと、実装が正しくても呼び出し側の値のassertは証明できません。

Nagini 1.3.1では、このソースを直接実行すると`Ensures`で`NotImplementedError`になります。
[テスト](../tests/test_list_contract.py)では、ソースのコピーを実際に検証し、
その同じコピーから既知の三つの`Ensures`行だけを除いて具体例を実行しました。
代入や呼び出し側のassertは残しています。一般的な契約の抽出機能ではありません。
非空という前提を通常実行で強制する仕組みや、空リストはこの実験の対象外です。
先頭以外の値を維持する事後条件も、この例には含めていません。

## 非負整数のリストを順に読む

[list_scan.py](../examples/list_scan.py)は、添字を0から増やす`while`で整数リストを足します。
入力は全要素が非負という前提に限定し、途中の合計と最後の結果が非負であることを検証しました。
`Forall(values, lambda value: value >= 0)`は、全要素について同じ条件を指定する記法です。

ループ不変条件には、読み取り権限、入力の非負性、添字の範囲、途中の合計の非負性を置きます。
不変条件は各繰り返しの途中で維持される情報を検証器へ伝えるためのものです。
権限の不変条件だけを除くと、ループ内のリストに対する前提で権限不足になりました。
計算自体は変えていないため、そのコピーの通常実行は正しい合計を返します。

この例は通常のPythonでそのまま実行できました。
負の要素を読んだ場合は、通常の`assert values[i] >= 0`で拒否します。
`Requires`や`Invariant`自体は実行時の条件を強制しません。
空・単一・複数要素、0、大きな整数の具体例で組み込みの`sum`と一致しました。

ただし、静的仕様は正確な合計値を保証しません。
足し算を省いて0を返すコピーも非負性の証明を通り、実行テストでは不一致になります。
リスト走査の停止性、合計の完全な事後条件、呼び出し側への権限返却は今回の対象外です。
詳細は[走査の比較](proofs.md)を参照してください。

## 整数の辞書から値を読む

[dict_read.py](../examples/dict_read.py)は、`dict[int, int]`から指定したキーの値を返します。
キーが存在しなければ0です。たとえば`{1: 7}`のキー1は7、キー2は0になります。
確認した操作は`key in values`、`key not in values`、`values[key]`と条件分岐です。
`dict.get`は実行テストの期待値を作るために使い、静的検証の対象にはしていません。

読み取りの前提は`Requires(Acc(dict_pred(values), 1 / 2))`です。
`dict_pred`は辞書の内容を扱うための検証上の権限を表す記法です。
キーが存在することを分岐で確認してから添字で読み、
存在時は対応する値、不在時は0になるという最後のassertを検証できました。

別のキー`key + 1`を読むコピーは、そのキーの存在を保証できないため拒否されました。
権限の前提を除くコピーはキー存在の判定で権限不足になり、
読み取り権限のまま値を代入するコピーも代入の前提で拒否されました。

通常のPythonでもそのまま実行でき、空、キーの有無、ゼロ、負数、大きな整数を確認しました。
ただし読み取り権限の宣言は、実行時の辞書を読み取り専用に変えません。
入力が変わらないことは具体例の実行テストで確認し、呼び出し側への事後条件にはしていません。
正しい書き込み・削除・走査、文字列キー、別名参照や並行実行は未確認です。
詳細は[辞書の比較](proofs.md)を参照してください。

## 整数の状態を持つクラス

[counter_contract.py](../examples/counter_contract.py)は、整数属性`value`を持つ`Counter`です。
`__init__`で初期値を設定し、`increment`で1増やします。
属性を明示する最小の検証モデルとして公開属性を使い、属性を隠蔽する契約は試していません。

初期化の事後条件は属性の読み書きの権限と初期値です。
更新の前提は同じ属性の権限、事後条件はその権限の返却と`Old(self.value) + 1`への更新です。
`Old`はメソッドに入る前の値を表します。
呼び出し側は初期値と一回目・二回目の更新を、実装の中身ではなくこれらの契約から検証できました。

初期値を1ずらすコピー、2ずつ増やすコピーはそれぞれの事後条件で拒否されました。
更新の値の保証を省くと呼び出し側のassertが証明できず、
読み取り権限だけを返すと次の更新呼び出しで権限不足になりました。

導入済みNagini 1.3.1では、通常のPythonで直接初期化すると`Ensures`で例外になります。
[テスト](../tests/test_counter_contract.py)では同じソースを検証し、
既知の四つの`Ensures`宣言だけを除いたコピーで通常実行を確認しました。
0・正数・負数・大きな整数で初期値と二回の更新が一致しました。
これはこのファイル専用の除去であり、一般的なクラスの抽出を保証するものではありません。
継承、プロパティ、複数属性、別名参照、並行実行やクラス全体の不変条件は未確認です。
詳細は[クラスの比較](proofs.md)を参照してください。

## 整数除算の境界条件

[division_boundaries.py](../examples/division_boundaries.py)は、正の除数に限定して商と余りを返します。
確認した記法は`//`、`%`、整数の乗算と加算、二つの整数のタプルです。
最後に`numerator == quotient * divisor + remainder`と`0 <= remainder < divisor`に相当するassertを検証しました。
たとえば分子-7、除数3では商-3・余り2となり、`-7 == -3 * 3 + 2`が成立します。

静的検証の前提は`Requires(divisor > 0)`です。
通常実行では別の`assert divisor > 0`を演算の前に置き、0と負の除数を拒否します。
`Requires`自体が実行時に不正な入力を弾く仕組みではありません。

商を1ずらすコピーと余りに除数を足すコピーは、再構成の等式で拒否されました。
前提と実行時のassertを両方除くコピーは、整数除算の前提で拒否され、
通常実行でも除数0で`ZeroDivisionError`になりました。
この例の元のソースは契約宣言を除去せず通常のPythonで実行できました。
0、除数1、正負の分子、大きな整数の具体例で`divmod`と一致しました。
`divmod`自体の静的検証や、負の除数、浮動小数点数、例外の捕捉、呼び出し側の事後条件は対象外です。
詳細は[境界条件の比較](proofs.md)を参照してください。

## 記録する内容

各題材では、使ったPythonの機能、満たすべき仕様、必要な注釈、検証成功、
狙った理由での失敗、実行テストの結果、保証が届かない範囲を記録します。
たとえば「リストを検証できた」とだけ書かず、読み取りだけか、内容を書き換えたか、
どの性質を検証したかが分かる粒度で記録します。
性能比較よりも、こうした確認範囲と仕様を先に固定する手順を重視します。


## 独立した一般階乗契約と偽6次多項式

非負整数全体の `Requires(n >= 0)` と `Ensures(Result() == fac(n))` を正誤の両実装に固定した。
`fac` は0で1を返し、正の入力で `n*fac(n-1)` を返す独立Pureモデルである。
再帰正例は実検証に成功し、有限例0〜4を全通過する偽6次多項式は分岐なしHorner形で
一般事後条件の違反として拒否された。5の通常実測は偽物676、数学的階乗120。
元式とHorner形の同値は整数係数展開と各連続整数積の可除性で確認する。
未証明の数学性質をAssumeやTrustedで注入していない。

Pureモデルの停止性を独立証明した結果ではなく、通常実行にはPythonの再帰上限がある。
while版の不変条件保存は証明未達だった。探索の例外・元積形式の時間切れを
最終的な正例成功と混同しない。詳細・再現コマンド・実診断は[検証の記録](proofs.md)を参照。

## 任意長リストへの末尾追加

[list_append.py](../examples/list_append.py)では、全書き込み権限を持つ任意長の整数リストへ一つ追加する。
空リストも含み、要素の符号・値・長さは前提で限定しない。
Ensuresは権限返却、長さ1増、旧全要素保存、新末尾一致を呼び出し側へ返す。
Old(ToSeq(values))は関数に入る時点の独立した要素列を表し、ForallとImpliesで
旧長さ未満の全添字について値が保たれると指定する。
呼び出し側は契約で全内容を確認し、返された書き込み権限も利用できた。

通常実行には既知四宣言だけを固定照合して除く専用コピーを使う。
別名参照・並行更新・権限を持たない呼び出しは未確認。
正誤比較、赤から緑の実測、診断位置と通常実行の詳細は[追加の実験](proofs.md)を参照。
