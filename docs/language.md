# Pythonのどの機能を検証材料にできたか

[READMEに戻る](../README.md)。検証の書き方は[仕様と検証](proofs.md)、
実行手順は[環境](environments.md)を参照してください。

この文書は、このリポジトリで実際に試したPythonの機能と必要だった注釈を記録します。
Naginiの対応機能を網羅した一覧ではありません。
「未確認」は、このリポジトリでは試していないという意味で、非対応とは区別します。

## 今回の例で確認したこと

2026-10-10時点の結果です。整数の絶対値と、整数の範囲の和という小さな題材での確認です。

| 機能・記法 | 題材 | 結果・必要だった条件 |
|---|---|---|
| `int`の引数と返り値 | 絶対値 | 型注釈を付けて検証できた |
| 比較・単項マイナス・`or` | 非負条件と絶対値の条件 | 二つの条件を検証できた |
| `if`、代入、`return` | 負数かどうかで分岐 | 正しい分岐は成功し、負数の分岐を壊すと失敗した |
| 通常の`assert` | 関数内部で結果を確認 | 実行時の具体例の検査にも、Naginiの静的検証にも使えた |
| 関数呼び出し | 絶対値を受け取る`caller` | 必要な返り値の保証を契約で宣言すると検証できた |
| `Ensures`、`ResultT` | 返り値の契約 | Naginiの仕様用記法。通常のPythonの機能ではない |
| `while`、加算・乗算、`+=` | 0からn未満までの和 | 範囲と途中の和を表す不変条件で最後のassertを検証できた |
| `Requires`、`Invariant` | ループの入力条件と途中の条件 | 検証用の宣言。この例では通常実行も可能だが、宣言自体が実行時に条件を強制するわけではない |

リスト・辞書・集合、クラス、可変状態、例外、外部ライブラリ、
ファイルやネットワークの入出力は未確認です。
公式の機能説明は[NaginiのREADME](https://github.com/marcoeilers/nagini)と
[仕様言語の説明](https://github.com/marcoeilers/nagini/wiki)を参照してください。
公式の説明だけを読んだ機能を、この表の実測結果には含めません。

## 検証できることと、Pythonで実行できること

通常のassertを使う[absolute.py](../examples/absolute.py)はPythonで実行でき、
[実行テスト](../tests/test_absolute.py)で選んだ入力について組み込みの`abs`と一致しました。

契約付きの[absolute_contract.py](../examples/absolute_contract.py)を直接実行するには、検証用の宣言を取り除く必要があります。
導入した版で`absolute(1)`を通常のPythonから直接呼ぶと、返り値を表す`ResultT(int)`が
`None`となり、`>= 0`の比較で`TypeError`になります。
2026-10-10に、[抽出スクリプト](../scripts/extract_absolute.py)で元のソースをNaginiで検証し、
二つの`Ensures`宣言と専用importだけを除去したコピーを実行できました。
計算する分岐・返り値と、呼び出し側の通常のassertは残しています。
負数・ゼロ・正数・大きな整数について、返り値が組み込みの`abs`と一致し、
呼び出し側も実行できることをテストしました。
生成手順は[環境の説明](environments.md)を参照してください。

この抽出は、今回のファイル構成と二つの契約宣言に限定した自作の処理です。
仕様や構成が想定と違えば停止し、実行部分に`Ensures`や`ResultT`が残る場合も拒否します。
ループ不変条件、別の契約、検証用の型などを一般的に除去する機能は試していません。
静的検証と、生成されたコピーの実行テストを合わせて確認した範囲の結果です。

## whileループの例を通常のPythonで動かす

[sum_range.py](../examples/sum_range.py)は、0からn未満までの整数を順番に足します。
たとえば`sum_range(4)`は`0 + 1 + 2 + 3`で6、`sum_range(0)`は0です。
このファイルは、導入済みのNagini 1.3.1の`Requires`と`Invariant`をimportしたまま
通常のPythonで実行できました。返り値を参照する`ResultT`や`Ensures`は使っていません。
前回の絶対値専用の抽出処理を、ループ用に拡張した結果ではありません。

`Requires(n >= 0)`は静的検証の入力条件です。通常のPythonで入力を拒否するためには
別のチェックが必要で、この例は`assert n >= 0`も置いています。
`Invariant`は検証時にループの途中で保たれる条件を伝える宣言で、
通常実行時に条件が真であることを強制する機能ではありません。
最後の通常のassertは、静的検証でも実行テストでも確認しています。
実行テストはassertが有効な通常のPythonで行い、`python -O`は対象外です。

検証の仕様は関数内の最後のassertに置いています。
返り値の保証を別の呼び出し側へ伝える契約や、一般的な停止性の検証は今回の対象外です。
詳しくは[ループの実験](proofs.md)を参照してください。

## 記録する内容

各題材では、使ったPythonの機能、満たすべき仕様、必要な注釈、検証成功、
狙った理由での失敗、実行テストの結果、保証が届かない範囲を記録します。
たとえば「リストを検証できた」とだけ書かず、読み取りだけか、内容を書き換えたか、
どの性質を検証したかが分かる粒度で記録します。
性能比較よりも、こうした確認範囲と仕様を先に固定する手順を重視します。
