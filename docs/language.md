# Pythonのどの機能を検証材料にできたか

[READMEに戻る](../README.md)。検証の書き方は[仕様と検証](proofs.md)、
実行手順は[環境](environments.md)を参照してください。

この文書は、このリポジトリで実際に試したPythonの機能と必要だった注釈を記録します。
Naginiの対応機能を網羅した一覧ではありません。
「未確認」は、このリポジトリでは試していないという意味で、非対応とは区別します。

## 今回の例で確認したこと

2026-10-10時点の結果です。いずれも整数の絶対値という小さな題材での確認です。

| 機能・記法 | 題材 | 結果・必要だった条件 |
|---|---|---|
| `int`の引数と返り値 | 絶対値 | 型注釈を付けて検証できた |
| 比較・単項マイナス・`or` | 非負条件と絶対値の条件 | 二つの条件を検証できた |
| `if`、代入、`return` | 負数かどうかで分岐 | 正しい分岐は成功し、負数の分岐を壊すと失敗した |
| 通常の`assert` | 関数内部で結果を確認 | 実行時の具体例の検査にも、Naginiの静的検証にも使えた |
| 関数呼び出し | 絶対値を受け取る`caller` | 必要な返り値の保証を契約で宣言すると検証できた |
| `Ensures`、`ResultT` | 返り値の契約 | Naginiの仕様用記法。通常のPythonの機能ではない |

ループ、リスト・辞書・集合、クラス、可変状態、例外、外部ライブラリ、
ファイルやネットワークの入出力は未確認です。
公式の機能説明は[NaginiのREADME](https://github.com/marcoeilers/nagini)と
[仕様言語の説明](https://github.com/marcoeilers/nagini/wiki)を参照してください。
公式の説明だけを読んだ機能を、この表の実測結果には含めません。

## 検証できることと、Pythonで実行できること

通常のassertを使う[absolute.py](../examples/absolute.py)はPythonで実行でき、
[実行テスト](../tests/test_absolute.py)で選んだ入力について組み込みの`abs`と一致しました。

契約付きの[absolute_contract.py](../examples/absolute_contract.py)は現段階では検証用です。
導入した版で`absolute(1)`を通常のPythonから直接呼ぶと、返り値を表す`ResultT(int)`が
`None`となり、`>= 0`の比較で`TypeError`になります。
契約を除去して同じ実装を実行する手順は未確認です。
静的検証に成功したことを、そのファイルを直接実行できることと取り違えないでください。

## 記録する内容

各題材では、使ったPythonの機能、満たすべき仕様、必要な注釈、検証成功、
狙った理由での失敗、実行テストの結果、保証が届かない範囲を記録します。
たとえば「リストを検証できた」とだけ書かず、読み取りだけか、内容を書き換えたか、
どの性質を検証したかが分かる粒度で記録します。
性能比較よりも、こうした確認範囲と仕様を先に固定する手順を重視します。
