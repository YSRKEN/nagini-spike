# 時間切れ時の検証プロセス回収

## 仕様

検査単位の時間切れでは、その起動単位の親・子・孫だけを終了し、終了を待つ。
独立した合成プロセスを生存対照にして、他の作業を巻き込まないことを確認する。
親ラッパーが先に終わっても、起動単位に属する子孫を残さない。
回収できなければ環境故障として報告し、成功・誤実装拒否・Python機能の非対応にしない。
捕捉した標準出力・標準エラーとtimeout診断をログへ保存し、TimeoutExpiredを維持する。
個別検証の上限90秒は維持する。新規依存と外部通信は使用しない。

独立合成テストを先に実行し、現実装で子孫が残ることを赤で確認する。
Windowsでの限定保証をPython機能台帳の支持範囲と混同しない。

## 実装と限定範囲

Windowsの検査ごとに無名Job Objectを作り、終了時回収を設定する。
実体のCPythonで起動した待機用プロセスを、Popenが保持するハンドルでJobへ所属させる。
所属設定が成功した後だけ検査本体を起動するため、venvラッパーの子起動との競合を避ける。
PIDの全体列挙や実行ファイル名による終了操作は使用しない。
時間切れではそのJobだけを終了し、所属数がゼロになるまで最大5秒待つ。
原出力をUTF-8で保存し、独立したtimeout診断を追加してTimeoutExpiredを伝える。
割当・回収失敗はOSErrorとして伝える。元の検査分類へ成功を追加しない。

CPythonのWindows実装が保持するプロセスハンドルと実体の実行ファイルを使用する。
Jobに所属できない実行環境では検査本体を起動せず失敗する。
他OSは既存のsubprocess.run経路で、子孫回収を保証しない。
既存サーバーへの処理委譲など、Jobの子孫ではない外部プロセスは対象外。
標準入力を必要としない既存の検査コマンドだけを対象とする。

## 証拠

- [赤試験](evidence/timeout-cleanup-red.log): 既存実装で合成子孫の残留を確認。
- [独立試験](evidence/timeout-cleanup-green.log): パイプ継承、親先行終了、通常親終了後の子孫、独立対照生存、割当失敗、本体出力保存を確認。
- [実Nagini制御試行](evidence/timeout-nagini-control.log): 5秒制限を5.036秒で返却し、Job所属3プロセスから0へ回収した。

実制御試行ではZ3の起動と実行ファイル識別を取得していない。
合成孫の回収成功を、実Z3時間切れの直接観測と同一視しない。
Python機能台帳の未確認件数と各判定は変更しない。
pytest全体の1200秒、個別検査の90秒制限は維持する。

独立対照も実体CPythonで起動し、保持したPopenハンドルで終了・待機する。
試験用子孫の非常時片付けは記録PIDと作成時刻を保持ハンドルで照合する。

## 最終全検査と時間制限

[最終全検査ログ](evidence/timeout-cleanup-final-check.log)では、lint・整形・strict型検査、
224テスト（1038.83秒）、実Naginiの正例成功・同契約の誤例拒否を確認した。
全体1068.77秒、終了コード0。
pytest上限1200秒との差は、新しい全実測で161.17秒だった。
今回の検査では1200秒を維持する。個別90秒も維持する。
将来の題材追加では全体を測り直し、上限近くなら余裕を再評価する。

正常経路では当該所有ツリーの実NaginiとZ3起動を直接観測し、
終了後に当時PIDと作成時刻に一致する生存が0であることを確認した。
時間切れ時の実Z3回収を直接観測したという主張にはしない。
5秒制御試行はassignをPIDからOpenProcessで取得する段階の実装で行った。
その後、起動境界を保持したPopenハンドルへ改善した。
最終版のtimeout・割当失敗・正常親終了後の子孫回収は独立合成試験で確認し、
最終版の通常実Nagini経路はこの全検査で確認した。

赤試験の原出力に当時のfixtureを含む失敗トレースを保存している。
仕様と赤テストは実装前に固定したが、仕様赤の別コミットは作っていない。
