# 辞書不在の結果契約と呼び出し側の安全な読取

元の問いは「キー不在の結果契約を呼び出し側へ返し、その契約だけで辞書アクセスの安全性を証明できるか」。
全権限の任意長dict[int,int]と任意整数keyを扱い、不在ならNone、存在なら元値を返す。
権限返却・長さ不変・全旧キーの存在と値保存・余分キーなし・None iff不在・非None値一致を一般契約にする。
入力を有限化せず、Assume/Trustedを使わない。

呼び出し側はlookupを呼び、Noneなら任意整数defaultを返す。
非NoneならOptional値を返すだけでなく、実際にvalues[key]を読み直す。
事前条件にキー存在を置かず、結果契約から存在と読み取り権限を得る。
呼び出し側にも全内容・長さ・権限の保存と返却値を指定する。
Pure/Inlineは使っていない。導入済みcall.pyの一般関数呼出とmethodcallnode生成経路を再照合し、
今回の呼び出しが本体展開ではなく契約付き呼出である根拠をdict-missing-call-model.jsonへ保存した。

最初にreturn None stubと成功期待テストを固定した。
最初の全キー同値と全値保存を別量化する形は個別90秒で時間切れとなり、証明拒否とは扱わない。
同じ保存仕様を「旧キーなら存在し旧値一致」と「現キーなら旧キー」の二つの量化へ表現し直した。
その赤stubはNone iff不在@31.12--31.53の事後条件で拒否され、pytest1failed50.15秒。
赤コミットは787ec8d。量化形式の違いと処理時間はこの試行の観測であり、一般的な性能保証ではない。

正実装はキーの不在分岐と一読取だけ。初回正例とcallerは終了0、Verification successful、50.60秒。
同じ契約で存在キーNone、不在キー整数、存在値+1の三つの誤返却を個別に比較する。
いずれも辞書を変更せず、保存条件を壊す誤例ではない。
最終整形後の位置と全文診断をtest_dict_missing.pyで必須照合し、失敗は各一つだけを要求する。

通常実行は空辞書、不在キー、存在する零・負・正の値、巨大整数キー/値の7例と、
各例でdefaultを負・零・正の3種類に変えた呼出側を別JSONに保存する。
三誤例も有限具体例で誤返却を照合する。これは任意入力の一般静的証明とは別の証拠である。
有限例の通常実行は契約宣言2Requires/12EnsuresだけをASTから除去して同じ実装を実行する。

全権限を前提とする単一辞書の読取に限定する。共有別名・並行変更・分数権限の返却・
KeyError送出/捕捉・削除・ループ・外部I/Oはこの題材で確認していない。
元optional-returnは検索一般の問いなので、この辞書題材だけから完了へ変えない。
全体は未完で、実台帳の完了候補検査は実行しない。

最終対象4testsは211.17秒で成功。正例50.91秒、存在None60.62秒、不在整数48.56秒、値+1は46.91秒。
存在None/不在整数は@42.12--42.53、値+1は@43.12--43.55の各単独事後条件拒否。
既存全pytest773.99秒に今回の対象211.17秒を加えた985.16秒は事前見込みであり、
全検査の実測ではない。全pytest1200秒、個別Nagini90秒、外側1500秒を維持する。

最終scripts/check.pyは終了0。通常台帳整合性・表一致・lint・53ファイル整形・strict型（0エラー）・全pytest218件（1090.06秒）・末尾Nagini正例11.97秒と狙ったAssert誤例11.50秒が成功。全体1118.99秒。保存証拠はdocs/evidence/dict-missing-final-check.log。pytest上限1200秒まで109.94秒で、追加題材時は実測に基づき制限を再評価する。個別90秒の時間切れ後に当該NaginiとZ3子が残った観測があり、全子孫回収と診断保存の機械保証は未確認。これは道具の課題であり、Python機能の非対応や誤実装拒否とは分類しない。別題材で制御試行するまで未解決を維持する。
